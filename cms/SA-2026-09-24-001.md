## Executive Summary

This report presents the findings of a security audit conducted on the CMS project (v1.0.82), a C++20 content management HTTP server built on Boost.Beast/Asio with MongoDB (mongocxx 4.6.0 / mongoc 2.5.4), cmark, fmt, and spdlog, deployed as a distroless container listening on `0.0.0.0:10000`.

The audit examined HTTP request handling, static file serving, MongoDB query construction, HTML rendering, TLS/transport security, secrets handling, resource controls, container hardening, dependency management, and alignment with OWASP Top 10 and MongoDB/container security practices.

**Overall Assessment**: The codebase shows good fundamentals — `GET`/`HEAD`-only handler, naive but present `..` traversal guard, `from_chars`-validated integer post IDs, attacker-influenced values passed to MongoDB as typed BSON builders (not string-concatenated queries), lower-bounded Meson dependencies, pinned `cmark 0.31.2`, `distroless/cc-debian13:nonroot` runtime with `USER nonroot`, and exclusion of `.env`/keys via `.dockerignore`. No classic buffer overflow, command injection, or direct NoSQL injection was identified.

The main residual risks are web-facing: **no TLS (plain HTTP only), stored-XSS-prone unescaped DB-to-HTML rendering with no CSP/security headers, weak path-traversal validation plus verbose filesystem errors, credential-bearing MongoDB URL logged in cleartext, OCSP explicitly disabled in the Docker build, and no rate limiting / request caps / vulnerability scanning**. No remotely exploitable RCE was confirmed, but XSS + HTTP eavesdropping + DoS preconditions are real.

**Risk Level**: Medium to High (High if exposed to internet or untrusted content authors; Medium if intranet-only with trusted DB writers behind a TLS-terminating reverse proxy)

## Findings

### High Priority Issues

#### 1. Transport Security Absence (Plain HTTP Only, No TLS)

**Severity**: High
**Status**: Requires Attention

**Description**: Server binds `0.0.0.0:10000` (`src/main.cpp:135-137`, `src/include/constants.h:13`) with Boost.Beast plain `tcp::acceptor`/`tcp_stream` (`src/include/httpServer.hpp:410-484`). No `ssl::context`, no certificate loading, no HTTPS redirect, no HSTS. All page/post/file traffic, `Host` headers, and any DB-derived content traverse cleartext. MongoDB connection itself may use `mongodb+srv` TLS, but client-to-CMS leg never does.

**Risk**: Passive eavesdropping, session/content theft, MITM content injection. Internet exposure without an external TLS terminator is unsafe.

**Recommendation**:
- Terminate TLS in front (reverse proxy: nginx/Caddy/Traefik/Cloudflare Tunnel) and document it as mandatory; add HSTS when TLS is present.
- Long-term: add native `boost::asio::ssl` support with minimum TLS 1.2 (prefer 1.3) and restricted ciphers, or explicitly mark this binary as "behind-TLS-proxy only" and fail startup with a warning if `REQUIRE_PROXY_TLS` is unset.
- Never expose port 10000 directly to the internet.

#### 2. Stored XSS via Unescaped DB Content Rendering, No CSP / Security Headers

**Severity**: High
**Status**: Requires Attention

**Description**: `Content::render` (`src/include/content.hpp:145-176`) concatenates `title`, `layout.header`, `content`, `layout.footer` directly into HTML with no escaping/encoding:

```cpp
titleTag.append(titleValue.data(), titleValue.size()); // content.hpp:153-155
content.append(headerValue.data(), headerValue.size()); // :158
content.append(contentValue.data(), contentValue.size()); // MODE_HTML :175
```

`MODE_HTML` is by-design raw HTML; `MODE_MARKDOWN` passes through `cmark_markdown_to_html` with `CMARK_OPT_DEFAULT` (no safe option). No `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` headers are set anywhere in `handle_request` (`src/include/httpServer.hpp:129-301`). `mime_type` fallback returns non-standard `application/text` (`httpServer.hpp:97`).

**Risk**: Any DB writer (compromised MongoDB, malicious author, seed-script contributor) achieves persistent XSS against all viewers. Missing CSP removes defense-in-depth; `text/html` responses from user-controlled titles/headers are directly executable.

**Recommendation**:
- Define trust boundary: if DB writers are not fully trusted, HTML-encode `title` at minimum; consider sanitizing `MODE_HTML` content (e.g., allow-list sanitizer) or serving author HTML in sandboxed iframe.
- Add `Content-Security-Policy` (e.g., `default-src 'self'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY/SAMEORIGIN`, `Referrer-Policy: no-referrer`.
- Fix `mime_type` default to `application/octet-stream`; do not serve `.php` as `text/html` if docroot may contain source.

#### 3. Dependency Version Management (Lower-Bounds Only, Unpinned Base / Actions, No Scanning)

**Severity**: High
**Status**: Requires Attention

**Description**: `meson.build:51-98` requires only `>=`: `boost >=1.80.0`, `fmt >=12.0.0`, `spdlog >=1.17.0`, `mongoc2-static >=2.5.4`, `libmongocxx1-static >=4.6.0`; `openssl` unversioned (`meson.build:74`). `Dockerfile:3` uses `FROM rfledesma/boost:latest` (opaque, mutable). `cmark 0.31.2` is pinned (`subprojects/cmark.wrap`) — good — but `fmt`/`spdlog` use wrapdb floating patches. GitHub Actions use mutable tags (`actions/checkout@v6`, `actions/cache@v6`, `docker/login-action@v4`, `hendrikmuhs/ccache-action@v1.2`, `github-script@v8`), not SHA pins. No Dependabot, CodeQL, Trivy/Grype, or lockfile scanning. `.gitlab-ci.yml` is an unmodified placeholder template.

**Risk**: Exposure to known/future CVEs in Boost/OpenSSL/Mongo drivers; supply-chain substitution via mutable base image or action tags.

**Recommendation**:
- Pin upper bounds or exact versions / lockfile for Boost, fmt, spdlog, mongoc/mongocxx, OpenSSL; pin base image by digest (`rfledesma/boost:<ver>@sha256:...`).
- Pin Actions to commit SHA with version comment; enable Dependabot + CodeQL + container image scan (Trivy) in CI.
- Remove or implement `.gitlab-ci.yml`; add scheduled `meson` + `apt` + driver CVE review.

### Medium Priority Issues

#### 4. Path Traversal / File Disclosure Validation Too Narrow + Verbose Errors

**Severity**: Medium
**Status**: Requires Attention

**Description**: Guard in `handle_request` (`src/include/httpServer.hpp:185-188`) is only:

```cpp
if (req.target().empty() || req.target()[0] != '/' ||
    req.target().find("..") != npos) return bad_request(...);
```

`path_cat` (`httpServer.hpp:102-121`) does no canonicalization, normalization, symlink resolution, or docroot-escape check. Encoded traversal (`%2e%2e%2f`, `%252e`, mixed case) is not rejected before `body.open(path.c_str(), ...)` (`httpServer.hpp:267`). On failure, raw `ec.message()` is returned to the client (`httpServer.hpp:276`: `server_error(ec.message())`), disclosing filesystem state. `mime_type` serves any readable file under docroot, including `.php` source.

**Risk**: Encoded/symlink bypass can read files outside `DOC_ROOT` (limited by `nonroot` user + container FS, but still config/secret disclosure). Error oracle aids enumeration.

**Recommendation**:
- Canonicalize (`std::filesystem::weakly_canonical`) after `path_cat` and enforce `path.starts_with(canonical_docroot)`; decode percent-encoding before `..` check or rely on `boost::urls::segments()` normalized view.
- Return generic `500`/`404` without `ec.message()`; log details server-side only.
- Validate `DOC_ROOT` at startup (exists, directory, no trailing `..`).

#### 5. Secrets Handling — Hardcoded Default + Cleartext Logging + Dev Defaults

**Severity**: Medium
**Status**: Requires Attention

**Description**: `src/main.cpp:95-104` hardcodes `mongodb+srv://user:password@localhost/...` fallback and warns with the full URL including credentials when `MONGODB_URL` is unset. When set, `src/main.cpp:98` debug-logs `MONGODB_URL => {value}` in cleartext. `resources/docker-compose.yml:14-15` uses `user`/`pass` dev credentials. No redaction helper exists.

**Risk**: Credential disclosure in logs/log aggregators; operators copy-pasting weak defaults to production; dev password reuse.

**Recommendation**:
- Remove hardcoded credentials; fail fast if `MONGODB_URL` is unset in production (allow insecure default only with explicit `ALLOW_INSECURE_DEFAULTS=1`).
- Redact password on all logs (`mongodb://user:***@host`); never log full URL even at `debug`.
- Rotate dev `user`/`pass`; add `.env.example` with placeholders; document Render/Docker secret injection for `MONGODB_URL`.

#### 6. Certificate Revocation Disabled (OCSP Off) + Unreviewed Mongo TLS Verification

**Severity**: Medium–High
**Status**: Requires Attention

**Description**: `Dockerfile:25-26` patches mongoc with `#define OPENSSL_NO_OCSP 1`, and `scripts/mongoc.sh` repeats it. This disables OCSP revocation checking for MongoDB TLS connections. No `tlsAllowInvalidCertificates`/`tlsCAFile` review or hostname-verification documentation was found in `src/main.cpp:112-121` (`mongocxx::uri` + `server_api v1` only).

**Risk**: Revoked/compromised MongoDB certificates accepted; MITM with revoked cert succeeds. Patch also touches cipher-list error path (`Dockerfile:29`), masking TLS misconfiguration.

**Recommendation**:
- Remove `OPENSSL_NO_OCSP` override; use current mongo-c-driver where OCSP/OpenSSL 3.5 regression is fixed upstream.
- Document required `MONGODB_URL` TLS options (`tls=true`, custom CA bundle mount, hostname verification); fail closed on TLS errors; test against revoked-cert fixture.

#### 7. Resource Exhaustion Protections (No Rate Limit, Unbounded Threads/Body)

**Severity**: Low–Medium
**Status**: Adequate but Limited

**Description**:
- Per-connection `stream_.expires_after(30s)` (`httpServer.hpp:359`) only; no per-IP concurrency/rate limit, no global connection cap, no header/body size limit on `http::request<http::string_body>` (`httpServer.hpp:323`).
- Thread pool from `hardware_concurrency()` overridable via `OVERRIDE_THREAD_COUNT` (`src/main.cpp:140-147`) with `toNumber` full-string validation (good) but clamped only at minimum (`max(1, n)`), no upper bound.
- Cache fixed at 25 entries / 900s TTL (`src/main.cpp:92`, `content.hpp:200`) — small but bounded; `KeyValueCache::set` returns `false` when full (content still served, just uncached — safe fail-open).

**Risk**: Single IP can exhaust threads/memory (slow-loris, large-body `GET`, many keep-alive connections); malicious `OVERRIDE_THREAD_COUNT=100000` forks thread-spawn DoS (env-operator only, but no guard).

**Recommendation**:
- Add per-IP concurrent + RPS limits (token bucket), global connection semaphore, Beast `header_limit` / `body_limit`.
- Clamp `OVERRIDE_THREAD_COUNT` to e.g. `[1, 2*hardware_concurrency or 64]`; log and reject out-of-range.
- Add request timeout + keep-alive idle timeout + access logs for abuse detection.

### Low Priority Issues

#### 8. Information Disclosure — Server Banner, Verbose Errors, OS Fingerprinting

**Severity**: Low
**Status**: Acceptable with Hardening

**Description**: Every response sets `Server: BOOST_BEAST_VERSION_STRING` (`httpServer.hpp:136,148,160,171,285,296`). `server_error` echoes `what`/`ec.message()` (`httpServer.hpp:157-166,276`). Startup logs OS/kernel/machine, RAM, CPU model/cores via `Environment::logOSinfo` (`environment.hpp:113-133`, called `main.cpp:73`). `Host`-based DB routing (`httpServer.hpp:191-195`: `quizbin.com` → `quizbin` else `localhost`) leaks routing logic; `page->getPage`/`post->getPost` warn with IDs.

**Risk**: Version fingerprinting aids targeted exploits; error + OS logs help attackers if logs leak.

**Recommendation**:
- Set `Server: CMS` or omit; return generic error bodies.
- Gate `logOSinfo` behind `CMS_DEBUG`; avoid logging `DOC_ROOT`/thread counts at `info` in production.

#### 9. Concurrency / Robustness — `gmtime`, Unlocked `empty()`, `assert`-Only Guard

**Severity**: Low
**Status**: Acceptable

**Description**: `stringUtil.hpp:149-157` uses `std::gmtime(&timeT)` (static storage, not thread-safe) under multi-threaded `ioc.run()` (`main.cpp:163-169`) — data race, garbled timestamps. `KeyValueCache::empty() const` (`keyValueCache.hpp:104`) reads `sizeCount` without the mutex (race; `size()` correctly locks). `StringReplacer` constructor `assert(!needle.empty())` (`stringUtil.hpp:64`) is compiled out with `b_ndebug=true` (`meson.build:9`); current needle is constant non-empty so not exploitable, but pattern is fragile.

**Risk**: Rare timestamp corruption / TSan failures; cache `empty()` torn read.

**Recommendation**:
- Use `gmtime_r`/`gmtime_s`; lock `empty()` or mark `sizeCount` atomic; replace `assert` with `throw std::invalid_argument` for empty needle.

## Code Quality Security Assessment

#### Input Validation
**Rating**: Good
- `GET`/`HEAD`-only enforcement (`httpServer.hpp:180`), `..` substring guard, `from_chars` strict integer parsing for `/posts/{id}` with `MAX_POST_URL_SEGMENTS=10` and `NONE_POST_ID` fallback (`httpServer.hpp:237-249`, `content.hpp:128-138`).
- Gaps: no percent-decoding normalization, no canonical docroot containment, no header/body size caps, `Host`-derived `dbName` allow-list is only two-way.

#### Memory Safety
**Rating**: Good
- Modern C++20 (`string_view`, `from_chars`, RAII `mongocxx::pool`, smart pointers); no `strcpy`/`sprintf`/`system()` found; `StringReplacer` precomputes output size and uses bounded `std::copy` (`stringUtil.hpp:112-143`).
- Gaps: `gmtime` race, `char buffer[40]` with `strftime` unchecked return (benign — format bounded), unlocked `empty()`.

#### Cryptographic Implementation
**Rating**: Weak (Missing)
- No server-side TLS at all; crypto delegated to MongoDB driver + OS OpenSSL. OCSP explicitly disabled (see Finding 6). No password hashing/auth (read-only CMS, no login — acceptable if documented).

## Compliance Assessment

- **A01 Broken Access Control**: No auth (read-only CMS by design); `Host`→`dbName` mapping is weak authorization — document trust model.
- **A02 Cryptographic Failures**: Fail — no TLS on client leg; secrets logged; OCSP off.
- **A03 Injection**: Good — BSON builders, no string-concatenated queries; stored XSS remains (A03 via DB content).
- **A04 Insecure Design**: Rate limiting / abuse cases missing.
- **A05 Security Misconfiguration**: Verbose errors, banner, missing security headers, dev default creds.
- **A06 Vulnerable Components**: Lower-bounds only, no scanning — needs pinning + SCA.
- **A07 AuthN Failures**: N/A (no login); ensure MongoDB itself requires strong auth.
- **A08 Data/Software Integrity**: Mutable base/actions tags, no SBOM/signing.
- **A09 Logging Failures**: No access logs; sensitive URL logging; OS-info over-logging. Add structured access + audit logs with redaction.
- **A10 SSRF**: N/A (no outbound fetch except MongoDB URI from env — validate scheme/host allow-list).

### CMS/HTTP-Specific Security
- `GET`/`HEAD` sequencing correct; `Host` routing minimal; 30s stream timeout present.
- No open relay/proxy issue (cf. SMTP); analogous file-serve path needs canonical containment.
- No `POST`/`PUT` write path — XSS is via DB trust boundary, not direct request injection.

## Recommendations

### Immediate Actions (High Priority)
1. Put TLS in front (mandatory reverse proxy) or add native HTTPS; do not expose `10000` directly.
2. Mitigate stored XSS: encode `title`, sanitize `MODE_HTML`, add CSP + `nosniff` + `X-Frame-Options`.
3. Fix traversal: canonicalize + docroot-containment check; suppress `ec.message()` to clients.
4. Stop logging `MONGODB_URL`/default credentials; fail fast without `MONGODB_URL`; rotate dev `user`/`pass`.
5. Remove `OPENSSL_NO_OCSP` patch; verify MongoDB TLS + hostname verification.

### Medium-term Improvements
1. Per-IP rate/concurrent limits, header/body caps, clamped `OVERRIDE_THREAD_COUNT`, global connection semaphore.
2. Pin all deps + base digest + Action SHAs; add Dependabot, CodeQL, Trivy, SBOM/cosign.
3. Add access logs (method, target, status, bytes, IP-behind-proxy) with secret redaction; alert on 404/500 spikes and disk/cache pressure.
4. Replace `gmtime` with `gmtime_r`, fix `empty()` locking, replace `assert` with exception; add TSan/ASan + unit tests (currently zero).

### Operational Security
1. Run behind WAF/reverse proxy; firewall `10000` to proxy only; keep `USER nonroot` + distroless.
2. Restrict `DOC_ROOT` permissions (`root:nonroot 0750`, files `0640`); no secrets/symlinks outside docroot.
3. Harden MongoDB: strong per-env users, IP allow-list, `tls=true` + CA bundle, least-privilege roles (read-only for CMS pool if possible).
4. Keep host + OpenSSL + drivers patched; rebuild base monthly; backup seed data (`resources/database/`) separately from code.

## Conclusion

Version 1.0.82 of CMS is a lean, readable Beast/MongoDB content server with sound query construction and a minimal container footprint, but it is **not yet internet-ready**: cleartext HTTP, unescaped DB-to-HTML rendering without CSP, bypassable file-path checks, cleartext secret logging, disabled OCSP, and absent rate limiting/scanning dominate residual risk.

With TLS termination, XSS/CSP hardening, path canonicalization, secret redaction, OCSP restoration, and dependency/CI pinning plus scanning, it can provide a solid foundation for self-hosted content serving.

**Risk Level**: Medium to High
**Recommended Actions**: TLS + XSS/CSP + traversal + secret-redaction fixes within 30 days; rate limiting, pinning/scanning, and logging as medium-term improvements.
